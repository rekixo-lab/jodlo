# ADR-0015 — Founder authorizes real provider connections and controlled production deployment

- **Decision date:** 2026-11-03 (Asia/Kolkata)
- **Status:** **ACCEPTED — current binding execution policy**, effective immediately.
- **Supersedes:** ADR-0004's *local-only-until-final-completion* timing, prohibition on remote Cloudflare provisioning/deployment, and any stale handoff wording that says real Google OAuth, Cloudflare account, live provider onboarding or deployment must be postponed *solely because the product is not finished*. ADR-0004 remains archived for history and for its still-useful no-staging preference, rollback and Finworkar boundary.
- **Reuses unchanged:** ADR-0006 shared Customer/Worker account, ADR-0007 Google-verified sessions, ADR-0008 Hindi/English, ADR-0009 explicit Worker publication, ADR-0011 889-Category *review target*, ADR-0013 Agora in-app voice, ADR-0014 Worker calling default OFF, and the founder-approved 2026-11-02 flat black/green UI.

## Founder instruction and engineering authorization

The founder explicitly instructed: stop deferring Cloudflare, Google and other real integrations, connect actual external services as needed for a production-ready JODLO, start controlled deployment work now, and explain **every indispensable manual owner action**, where to navigate, which values go where, and how to pull/build/install on a local Android phone. Do not demand fresh generic "करो" or integration permission for each engineering step.

**Authorized immediately:** review/create secure production configuration and deployment runbooks; use the dedicated JODLO Cloudflare account/project to provision actual production Worker, D1 and later R2/Queues/DO when needed; configure real Google Cloud OAuth client IDs and credential workflow; integrate real Agora/FCM/payment providers when their relevant journeys and policies are safe; run protected remote migrations, deployment and scoped production smoke checks *after the exact preflight evidence for each external action*. Preserve exact-head CI and real device/prod validation. No standing ban on remote deployment or provider onboarding remains.

**Not automatically true:** a real account is connected; required app/domain resource IDs or credentials are known; DNS/TLS is verified; Category inventory is content-reviewed/activated; Google sign-in or Agora signaling is operational; a payment is authorized; public traffic release, legal compliance, production security or on-device acceptance has passed. **Do not claim these without evidence.**

## Operating mode

1. **Real-first, never demo-as-live.** Build against actual Cloudflare Workers/D1 and real Google credentials, and test end-to-end with the real installed Android app. Synthetic/mocked data is permitted only in isolated automated CI, security/reproducibility tests and conspicuously labelled debug-only offline preview; it cannot substitute for provider acceptance or populate production. No invented real users, approval badges, listings, GPS, calls, balances or merchant transactions.
2. **Provisioning/deployment is now in scope.** Use a dedicated JODLO Cloudflare deployment, real D1 binding, production secrets, verified Google OAuth, DNS and protected environment. Respect the historic **no separate staging environment** preference unless the founder explicitly changes it. A limited access production canary and rollback are acceptable. GitHub push or untrusted PR must never automatically deploy or access production secrets.
3. **Manual owner actions are explicit and immediate.** Mark each as `NEEDS_DECISION_NOW`, `UPCOMING`, `BLOCKED_EXTERNAL`, or `DONE` in [Manual Actions](../MANUAL_ACTIONS.md) with instructions. Ask for **nonsecret configuration identifiers** only when useful; never request passwords, API tokens, account recovery material, OAuth client secrets, private keys, service-account JSON, payment OTPs, user data or real bearer tokens in chat, PRs or git.
4. **Production secrets reside in authorized systems only.** Use Cloudflare dashboard/Wrangler secret entry (never source control) and protected local configuration for public Android OAuth Web client ID and approved API origin. Only grant minimum provider/DNS permissions. Real Android client certificate SHA fingerprints, exact package name, OAuth consent configuration and Google user audience must match.
5. **Preserve fail-closed security and operational prerequisites:** server-side Google ID token verification, session/role checks, strong API limits, moderation, active reviewed Category source, privacy consent/data retention and deletion for real personal data, safe D1 migrations/backups, account/expense limits, logging/alerts/rollback, and genuine production smoke tests. Unknown call presence, anti-spam policy, RTC signaling/ack or payment receipts **must not be silently treated as approved**; Worker Agora receiving consent stays default OFF.
6. **No Finworkar mutations.** The old Firebase/Finworkar projects, accounts and apps are read-only references. JODLO production must use separately identified resources. Preserve privacy-by-default and any required human/legal/provider approval; a general technical work authorization is not a substitute for specific retention durations, numeric abuse windows, external account access, regulated service-category editorial review or financial transaction consent.
7. **Source of truth:** this ADR + [Real Integration Runbook](../REAL_PRODUCTION_CONNECTION_RUNBOOK_2026-11-03.md) + [Manual Actions](../MANUAL_ACTIONS.md) override contradictory *prospective instructions* in older docs. Historical paragraphs, old PR evidence and CI dates remain historical facts and must not be rewritten as if they never happened. Record verified status and links to current commits/runs after every milestone.

## Milestone sequence (real, checked and reversible)

- **P0:** founder connects/provisions actual dedicated Cloudflare account and confirms domain isolation; obtain real nonsecret D1/Worker/account bindings and billing limits. Write production-only Wrangler config with real IDs, not CI fake D1 placeholders.
- **P1:** secure minimal production Worker + D1, backup/migration procedure, rate-limit bindings, health/anonymous public read smoke and rollback; do not expose Google-auth operations until issuer/audience/limits and privacy are verified.
- **P2:** real Google Cloud console consent + Web OAuth client + Android OAuth client (package + debug/release SHA), server-side `GOOGLE_CLIENT_ID` configuration, actual Android -> Cloudflare sign-in and revoke test with owner-owned test identity.
- **P3:** founder-reviewed Category activation; actual Worker sign-in -> Category Search -> publish -> Customer discover/detail -> unpublish, with real cross-device state and access-control tests.
- **P4+:** real Agora/FCM/media/moderation/retention and eligible payments, each behind its own validated capabilities/policy and clearly reported evidence. Explicit access/traffic increase requires safety/performance and spend checks.

**Release language:** `authorized_to_integrate/deploy` is NOT `deployed`; `deployed` is NOT `ready_for_public_users`. Show what is real, what is blocked by external owner action, and which production workflows are still disabled.
