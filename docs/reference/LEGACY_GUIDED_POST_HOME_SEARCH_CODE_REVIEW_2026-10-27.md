# Legacy Finworkar Guided Add Post, Category Selection, Home and Search — source-level deep review

**Date:** 2026-10-27. **Mode:** READ ONLY. **Source SHAs verified equal their current GitHub main heads**, Android `0ad9ddd230439f76da363c6bbacdddb35288704f`, backend `f31d089953f68868108f5d475436842b55c10204`. This is static source analysis, **not** a real-device run, deployed-version audit, usability observation or proof that all old systems operate as expected. No legacy code/data/media/dependencies, Firebase credentials, Hinglish behavior, cloud resources or UI are transferred into JODLO.

## 1. Actual four-screen Android Guided Add Post

`GuidedAddPostActivity.java` has four explicit semantic constants **STEP_WORK=1, STEP_EXPERIENCE=2, STEP_LOCATION=3, STEP_REVIEW=4**, plus separate `pageOne`, `pageExperience`, `pageLocation`, `pageReview` containers in the single [layout XML](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/res/layout/activity_guided_add_post.xml#L137-L1040). [Source steps](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L100-L110) and [Next routing](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L1308-L1350).

1. **Work and category:** Worker types a work description or speaks using Android SpeechRecognizer (Hindi/English locale from old app). A 320ms debounced call to `searchFwCatalog` with generation and timeout guards returns up to three matches. A strong match fills **groupId, familyId, categoryId, names** and replaces user input with the **canonical category title**. Ambiguous/weak/no-match requires visible selection or manual picker, and user cannot advance without a category. Editing the typed description can invalidate a prior choice; changing category clears category-dependent pricing. Manual selection opens `CategoryPickerActivity`, which returns selected group, category and family ID and resolves the family name separately. This is **not free-text title publishing**. [Auto-suggestion](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L1411-L1510), [manual choice](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L911-L963), [Step 1 guard](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L1308-L1331).
2. **Experience and pricing:** The second screen shows experience chips (Fresher, 1–2, 3–5, 5+ years) and category-dependent pricing modes/units, including negotiable/contact. A category profile must contain allowed pricing units to publish. Amounts are conditionally validated by client and again by the backend. The `STEP_EXPERIENCE` Next handler proceeds without a distinct explicit experience-required guard; defaults/normalization are separately handled by backend. [UI wiring](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L874-L879), [price configuration](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L2019-L2182), [publish validation](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L2770-L2840).
3. **Location:** Current device location or an explicitly selected Google Places area. Stores display text, source, coordinates, accuracy, freshness and worker coverage radius (5, 10, 25, 50 km; 10 km fallback). A current location must be fresh within 10 minutes for a new publication; selected place/display and rough India coordinates are checked. The Android coordinator ingests trusted current location server-side; selected work location follows a distinct backend verification path. **This is old product logic, not JODLO's approved M-003 policy**. [Location validator](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L2487-L2526), [picker](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L2269-L2470), [coordinator](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/PostCreateCoordinator.java#L289-L345).
4. **Review and publish:** Review summarizes canonical category title, hierarchy context, experience, rate, location, radius and images. **At least one image** is required (up to 9 selected); local contact-text scanning/pixelation runs before upload, with backend verification/moderation of ownership and image content. Publish first validates, then calls `PostCreateCoordinator.create` and opens the success screen. Edit mode takes separate `PostUpdateCoordinator` path with content-version conflict recovery. [Review](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L2568-L2588), [publish](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L2590-L2690), [validation](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L2770-L2840), [image scanner](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/GuidedAddPostActivity.java#L2844-L2950).

The in-memory [SmartPostDraft](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/SmartPostDraft.java) keeps the typed **workQuery** separate from canonical persisted **title**. Android state restoration preserves category/hierarchy, price, location, images, current step and draft ID.

## 2. Guided publish path: exact Android → backend contract

[PostCreateCoordinator](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/PostCreateCoordinator.java#L42-L52) sequences account creation/attachment, trusted/selected location handling, already processed image uploads under owner/draft storage path, then server callable `createPost`. It uses a stable `draftId`, busy guard, explicit error types and **same-ID retry** after a network ambiguity; it avoids deleting uploaded images if server commit may already have happened. [Coordinator request](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/PostCreateCoordinator.java#L79-L133), [image upload](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/PostCreateCoordinator.java#L348-L420), [retry and cleanup](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/PostCreateCoordinator.java#L433-L535).

Backend [`AddPost.js createPost`](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/AddPost.js#L1108-L1533):

- Requires authenticated caller, resolves owner **from auth**, not client-provided owner ID. Checks existing owner/draft replay before doing work; validates `groupId/categoryId/familyId` against **canonical active catalog ancestry** (root/group/family/category), category selectable status, canonical localized title and allowed price units. [`fwCatalog.js`](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/fwCatalog.js#L119-L185).
- Validates recent current/trusted or explicitly chosen work coordinates, radius, no direct-contact in publicly displayed text; sanitizes/validates image ownership and moderation; checks blocked words. The old backend had credit/plan/premium/reward logic, **none of which is automatically JODLO policy**.
- Within Firestore transaction, rechecks idempotency; applies owner credit/count changes; stores post at `userPosts/{ownerId}/posts/{postId}` with **status='available'**, `groupId/familyId/categoryId`, canonical names, catalog schema/version, prefix keywords, price, experience, bounded location/geohash, photos, moderation, account snapshot; also writes a `postCreateDrafts` replay receipt and geo mirror. Saved-search notification occurs after transaction. [Transaction and quota](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/AddPost.js#L1253-L1348), [persisted post projection](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/AddPost.js#L1350-L1434), [post-write alerts](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/AddPost.js#L1504-L1517).
- Unlike old system, existing approved **JODLO** worker listing is category-only, immediate, no automatic verified badge, no required image/price/GPS. Do **not** silently introduce old four-screen mandatory fields or contact/credit/payment rules into JODLO.

## 3. Manual Group and Category choosing: two different screens

**Home browsing:** `HomeActivity` renders a horizontal **active catalog group chips** list (plus `All`). Tapping a Group opens [`CategoryBoardActivity`](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/CategoryBoardActivity.java#L158-L195); it lists categories for the group in a two-column grid, plus a special **View All** tile that returns group-level filtering (category ID null). [Home chip action](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeActivity.java#L322-L362), [board result](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/CategoryBoardActivity.java#L380-L393), [Home receives category](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeActivity.java#L263-L287).

**Posting:** [`CategoryPickerActivity`](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/CategoryPickerActivity.java#L169-L211) reuses the same board layout/list adapter but **requires a concrete child Category**; its View All click does nothing. Group list is loaded from catalog; selecting a Group fetches its active+selectable child categories; category click returns `groupId/groupName/categoryId/categoryName/familyId` to Guided screen. There is **no separate four-level Group → Family → Category → Service picker wizard** in these screens: Family is parent metadata attached to Category and Service leaf is used for matcher vocabulary, not saved as a selected service ID in the posting payload. [Picker return](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/CategoryPickerActivity.java#L169-L211), [fetch](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/CategoryPickerActivity.java#L228-L305).

[Catalog repository](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/FwCatalogRepository.java#L78-L92) reads `fw_categories/current/groups|families|categories` and caches group/category data tied to a verified root schema/version. Groups query `active==true` ordered by order; categories query `groupId`, `active==true`, `selectable==true` ordered by order. **Neither query checks whether the group/category currently has any visible posts.** [Group query](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/FwCatalogRepository.java#L125-L153), [category query](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/FwCatalogRepository.java#L156-L198). Root version changes invalidate caches. [State verification](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/FwCatalogRepository.java#L285-L346).

**Category-grid search** is **local in-memory text filtering** of the already loaded selected Group's category names using NFKC normalization and all-token substring matching, not a remote search or live-post count. [CategoryAdapter](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/CategoryAdapter.java#L50-L80), [CategorySearchMatcher](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/categories/CategorySearchMatcher.java#L8-L34). Group change clears existing query. Family is not a separate browse tab.

## 4. Home post listings, Search, filters, guest/nearby

- `HomeActivity` uses a RecyclerView/PostAdapter; group tabs originate from **catalog**, while posts come independently from `getNearbyPosts`. Selecting Group/Category updates filters and requests a new feed, not the catalog. Search EditText debounces 300ms. It first calls `searchFwCatalog` to infer a strong category (if any); weak, no-match and error cases fall back. [UI setup](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeActivity.java#L290-L419), [text debounce](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeActivity.java#L864-L881), [catalog resolution](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeActivity.java#L1569-L1633).
- `runGeoQuery` tries exact category at fallback stage 0, Group at stage 1 if available, text search at stage 2; empty responses can trigger broader fallback or radius expansion. **An exact selected Category is not guaranteed to remain the only category in results after a fallback.** [Filter request and fallbacks](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeActivity.java#L1685-L1795). Public/guest mode has its own preview handling. Post pages are sorted/merged and deduplicated, but no category-with-posts-only Group UI list is constructed. [UI results](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeActivity.java#L1949-L2025).
- Backend [`HomePosts.js getNearbyPosts`](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/HomePosts.js#L640-L785) branches guest vs signed-in. **Guest** may browse public `available` feed with bounded paging/query and reduced `guestPreview` fields (location masked), no trusted physical-location filter. **Signed in** must have recent **server-trusted** user location; geohash-bound scans filter by status, category or Group, optional keyword anchor, precise distance **and** posted worker coverage radius; deduplicate, exclude disabled owners, rank, paginate with a snapshot/revalidation strategy. [Guest projection and search](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/HomePosts.js#L240-L266), [public feed query](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/HomePosts.js#L534-L638), [nearby bound](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/HomePosts.js#L482-L531), [snapshot rechecks](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/HomePosts.js#L376-L479).
- Visibility requires post `status='available'` and moderator not hidden/removed, plus active owner; detail endpoint checks these again for non-owner and interaction permission/block relationship. [public eligibility](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/postPublicEligibility.js#L24-L44), [post detail](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/PostDetail.js#L143-L204). Old trust/premium/verification/pin ranking is historical only, **not approved JODLO behavior**.
- There are **three distinct search operations**, not one: (a) Group-specific local CategoryBoard/Picker name filter, (b) `searchFwCatalog` semantic/voice category inference using historic matcher vocabulary and Group/Family/Category/Service terms, and (c) `getNearbyPosts` over actual published posts using category/group/keyword/geography. [Matcher endpoint](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/fwCatalogSearch.js#L49-L120), [client](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeCatalogSearchClient.java), [posting client](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/posts/FwCatalogSearchClient.java).
- Service-level vocabulary can help infer Category, but the **post record is categorized by Category ID**, not by a chosen Service leaf ID. The historic 7,267 service leaves cannot be assumed to be 7,267 separately selectable posting options.

## 5. Precise static finding requiring follow-up (not proved live defect)

[`HomeActivity.runGeoQuery`](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeActivity.java#L1685-L1718) only sends free-text `searchText` to backend when `fallbackStage >= 2`. Every fresh search starts at **fallbackStage = 0** [here](https://github.com/rekixo-lab/finworkar-android/blob/0ad9ddd230439f76da363c6bbacdddb35288704f/app/src/main/java/com/finworkar/pro/ui/home/HomeActivity.java#L1636-L1683). If a nonempty query yields **no strong Category and no manually selected Group**, the first request can carry **no categoryId, groupId or searchText**; [backend guest/public and nearby handlers](https://github.com/rekixo-lab/finworkar-backend/blob/f31d089953f68868108f5d475436842b55c10204/functions/src/HomePosts.js#L640-L658) may then return unfiltered `available` posts. If the page is nonempty, the UI does not proceed to the stage-2 text filter. This is a **source-level likely search relevance gap**, not a measured live bug. Before JODLO adaptation, test a no-category-match query and verify the intended no-match vs broad-discovery semantics. Do not copy an untested automatic widening rule.

Other review risks, not rollout decisions: (1) catalog group/category queries do not gate by actual post availability; (2) retry/idempotency, canonical ancestry, media moderation and owner filters need equivalent behavior-specific tests if required; (3) old precise-location mandatory behavior and guest owner fields may conflict with new privacy requirements.

## 6. JODLO boundary after this study

**No implementation decision is changed.** JODLO already has Google-linked account + private worker draft, immediately publishable category-only listing **in an approved active category**, no automatic verified badge, bilingual catalog/search, opaque public listing fields, moderation-hidden filter, and synthetic safety rules. This source review does NOT approve all 889 legacy categories, all 7,267 service leaves, city-specific live matching, an image/price/GPS requirement, paid credits, call/chat, automatic trust labels, UI or deployment.

Founder-selected city **names** are Bilaspur and Raipur (ADR-0010). Category enablement and first customer flow remain **M-005 undecided**; personal location/consent/retention/delete **M-003 undecided**; design **M-004**, providers **M-006**, production **M-007**, real Google OAuth **M-008** remain gated. **Only Hindi (Devanagari) and English**. Historic matcher Romanized Hindi is read-only history, NEVER a permitted new JODLO language mode.
